# Open Source Self-Assessment

This document captures our organization's current state and goals for open source engagement across three key dimensions.

## Assessment Results

| Dimension | Current Level | Goals |
| --------- | ------------- | ----- |
| Consuming open source software | Ad-hoc | Defined |
| Contributing back to the open source projects you consume | Ad-hoc | Managed |
| Producing your own open source software | Ad-hoc | Managed |

## Level Definitions

![Open Source Levels](https://user-images.githubusercontent.com/6351798/58345546-d7b6b880-7e15-11e9-863b-803604593e43.png)

- **Ad-hoc** - a new or undocumented process is uncontrolled, reactive and unpredictable, typically driven by individuals without coordination or communication. Success depends on individual heroics.
- **Managed** - a process is partially documented, possibly leading to consistent results. Success depends on discipline.
- **Defined** - a process is documented, standardized, and integrated into other processes. Success depends on automation.
- **Measured** - the process is quantitatively managed. Success depends on measuring metrics against business goals.
- **Optimized** - the process is continually and reliably improving through both incremental and innovative changes. Success depends on reducing the risk of change.

## Action Plan

### Consuming Open Source Software
- Document current open source usage across projects
- Establish a process for evaluating and approving new open source dependencies
- Create guidelines for security and license compliance
- Implement automated scanning tools for dependencies

### Contributing Back to Open Source Projects
- Develop a policy for employee contributions to external projects
- Create a process for code review before external contributions
- Establish guidelines for attribution and licensing

### Producing Open Source Software
- Identify potential internal projects for open sourcing
- Develop criteria for determining when to open source internal code
- Create templates for documentation, contribution guidelines, and code of conduct
- Establish governance model for open source projects
